# RP-001 controlled production verification

Create seven non-customer identities through the normal production authentication administration boundary: an administrator and operator in controlled tenant A; an owner linked only to controlled owner/property A; an administrator or operator in controlled tenant B; a second owner linked only to controlled owner/property B; an authenticated tenant-A user without reporting permission; and a tenant-A user whose membership is revoked after creating a controlled export. Credentials and short-lived access tokens are delivered to the release operator outside the repository and must never be committed, logged, or pasted into evidence.

For the approved `tlafrentz+rp001-*` Gmail aliases, run `npm run reporting:bootstrap-verification` with `RP001_BOOTSTRAP_CONFIRM_PRODUCTION=I_CONFIRM_CONTROLLED_RP001_IDENTITY_BOOTSTRAP` and the server-owned Supabase environment. The idempotent bootstrap creates confirmed accounts with unrevealed random credentials, two synthetic workspaces, two synthetic properties, and bounded memberships. The release operator establishes each usable password through the normal production password-reset flow; the bootstrap never prints or stores credentials.

Create one synthetic property per controlled owner and only synthetic reporting records. Run `npm run verify:reporting:production` with `RP001_VERIFY_CONFIRM_PRODUCTION=I_CONFIRM_CONTROLLED_PRODUCTION_VERIFICATION`, the exact production URL, and the seven short-lived token variables named by the script. The tool emits status codes and a hashed target only. Complete report generation and artifact journeys interactively with the same identities; record IDs, counts, checksums, timings, and outcomes but no content or credentials.

For cleanup, set the server environment locally through the approved secret store and run `npm run reporting:expire-artifacts` with `RP001_CLEANUP_CONFIRM_PRODUCTION=I_CONFIRM_BOUNDED_REPORT_ARTIFACT_CLEANUP`. The operation selects at most the configured batch, deletes only the exact stored identity, and compare-and-sets its metadata to expired. Deactivate verification users and archive controlled reports afterward; preserve immutable audit rows. Never use broad SQL deletion.
