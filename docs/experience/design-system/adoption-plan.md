# Adoption Plan

Adoption is incremental. Existing products remain operational while the shared system proves its contracts.

## Phase 1 — Foundation

Implement tokens, typography, spacing, surfaces, primitives, and common states.

## Phase 2 — Shell and navigation

Implement the application shell, canonical typed navigation, Product Header, content containers, appearance behavior, and responsive composition.

## Phase 3 — Shared product patterns

Implement Health Summary, cards, tables, forms, filters, activity, history, and evidence-backed state patterns.

## Phase 4 — Reference product

Apply the complete system to **Workspace**. Validate composition flexibility, visual hierarchy, density, responsive behavior, accessibility, state handling, component APIs, and developer ergonomics before broader adoption.

## Phase 5 — Existing-product migration

Recommended order:

1. Executive Intelligence
2. Portfolio Intelligence
3. Learning Intelligence
4. Revenue Intelligence
5. Action Center
6. Investment Intelligence
7. Business operations

Migration priority may change with customer impact and component reuse, but it must not become a single platform-wide rewrite.

## Exit criteria

Each migration records the components adopted, exceptions, accessibility results, responsive results, visual regression coverage, removed duplication, and remaining debt. A phase advances when the reference implementation demonstrates stable APIs and no critical accessibility or workflow regression.

## Design artifact companion

Experience Design maintains the token reference, typography specimen, semantic color matrix, spacing and grid reference, inventory and state matrix, layout and responsive examples, navigation states, template examples, accessibility annotations, and light/dark examples. Written specifications remain canonical for product intent and governance.
