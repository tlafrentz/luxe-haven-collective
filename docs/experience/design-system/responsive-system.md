# Responsive System

**System:** Luxe Haven Application Design System v1  
**Status:** Canonical

Responsive behavior follows task priority, not a scaled-down desktop composition.

## Priority order

1. Current state and critical attention
2. Primary action
3. Primary workflow
4. Critical context
5. Supporting information
6. History

## Composition

| Viewport | Navigation | Workspace | Supporting content |
| --- | --- | --- | --- |
| Desktop | Persistent sidebar | Split views, wide dashboards, dense tables | Contextual rail or section |
| Tablet | Navigation drawer | Reduced columns and adaptive controls | Stacked or collapsible |
| Mobile | Drawer or full-screen panel | Single, sequenced primary task | Expandable below the task |

Split views become sequenced list and detail views on mobile. Local tabs may scroll or become a labeled selector. Tables should use fewer columns, record cards, or deliberate horizontal scrolling according to the comparison task; teams must not simply shrink them.

Context selectors and primary actions remain understandable and reachable. Bottom-fixed actions are allowed only when they do not cover content, validation, or navigation. Touch targets must be at least 44 by 44 CSS pixels.

## Density

- **Comfortable:** onboarding, configuration, and authoring
- **Standard:** reports, intelligence, properties, and bookings
- **Dense:** conversations, operational tables, and action queues

Density remains consistent within a workspace. Mobile reduces information before reducing legibility.

## Acceptance

Every template is reviewed at desktop, tablet, 320 CSS-pixel mobile width, 200% zoom, long-label, missing-data, and high-density conditions.
