# Guest Communications Product Blueprint

| Field | Definition |
|---|---|
| Mission | Coordinate every guest conversation across the hospitality journey |
| Primary users | Owner, operator, property manager, guest services |
| Business question | Which guests require attention? |
| Primary action | Reply to the selected guest |
| Health model | Work queue: open, needs attention, waiting, scheduled, urgent |
| Dominant pattern | Master-detail |
| Density | Dense |
| Local navigation | Tabs for Inbox, Needs Attention, Scheduled, Templates, Search, Archive; record navigation for conversations |
| Supporting information | AI assistance, reservation/property context, guest journey |
| History model | Conversation timeline inside the primary workspace |
| Success metrics | Response time, unresolved urgent conversations, guest issue resolution |
| Out of scope | Guest identity, reservations, property records, automatic AI sending |

First use explains that PMS or reservation connections create conversations. Attention identifies the guest impact and response priority. Degraded state distinguishes channel unavailability from accessible historical threads. Empty results preserve configured inbox context. Permission state respects property-level access. Archived conversations are retained and restorable.

Mobile order is queue state, reply action, selected conversation, essential reservation/AI context, then timeline.
