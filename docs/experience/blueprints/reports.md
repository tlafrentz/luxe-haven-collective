# Reports Product Blueprint

| Field | Definition |
|---|---|
| Mission | Publish decision-ready Hospitality Performance Management narratives |
| Primary users | Owner, investor, asset manager, portfolio manager |
| Business question | What should I communicate to this audience? |
| Primary action | Generate report |
| Health model | Publishing: recent, scheduled, shared, drafts, delivery issues |
| Dominant pattern | Dashboard-to-detail with a guided generation flow |
| Density | Standard |
| Local navigation | Edition tabs; Audience → Type → Scope → Review → Publish steps |
| Supporting information | Templates, delivery status, audience guidance |
| History model | Immutable report version list |
| Success metrics | Reports published, successful deliveries, stakeholder engagement |
| Out of scope | Intelligence calculations, live dashboards, source-data mutation |

First use invites creation by audience. Attention identifies failed delivery or an unfinished review. Degraded state describes missing source intelligence without generating fabricated metrics. Permission state separates generation, review, publication, and sharing. Archived snapshots remain immutable and accessible.

Mobile prioritizes publishing condition, Generate Report, current library or guided step, delivery support, then version history.
