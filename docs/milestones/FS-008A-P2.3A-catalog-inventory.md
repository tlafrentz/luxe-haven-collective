# FS-008A-P2.3A — Catalog boundary inventory

All Furnishing catalog writes use the canonical application denial before any
database write or revalidation. The existing PostgreSQL trigger remains the
last-line defense.

| Entry point | Mutation/effect | Guard | Database protection | Customer visibility | Test |
|---|---|---|---|---|---|
| `furnishing-catalog` admin actions | Product, offer, retailer, preferred-offer writes | `assertFurnishingActivationMutationDisabled` | FS-008A catalog trigger | No revalidation on denial | catalog guard test |
| XLSX/file import | Parse and import catalog rows | same guard before file/database work | trigger | No publication/cache effect | catalog guard test |
| `furnishing-packages` actions | Package/item/alternative/version writes | same guard before mutation | Furnishing RLS/triggers | No projection effect | catalog guard test |
| Bulk/provider/scheduled refresh | No active application call site found | canonical guard required at future entry | trigger | Denied by default | envelope/guard regression |
| Product/offer activation/publication | No separate active application path found | catalog mutation guard + trigger | trigger | Unpublished content remains hidden | migration regression |
| Retry/replay/direct RPC | No active bypass path found | server boundary and trigger | trigger | No cache/index/revalidation effect | direct-denial regression |
| Customer projections/deep links | Read paths remain ordinary authorized reads; unpublished rows are not activated | activation state remains disabled | status/visibility constraints | No unpublished publication | safe-state tests |

Non-Furnishing catalog and commerce behavior is unchanged. No provider request,
catalog mutation, cache invalidation, search indexing, or customer publication
is performed while FS-008A is disabled.
