# FS-008A-P2.3B — Installation and customer-effect inventory

`scope(projectId, true)` is the canonical application write boundary for all
Furnishing installation actions. It evaluates the FS-008A activation policy
before any database, storage, cache, provider, calendar, or notification effect.

| Entry point | Mutation/effect | Guard/protection | Notification | Denied behavior | Test |
|---|---|---|---|---|---|
| `startInstallationAction` | Installation project, tasks, checks, events | write scope + PostgreSQL trigger | None enqueued | Stable activation denial; no progress | guard test |
| `updateInstallationTaskAction` | Task/status completion | write scope + RLS/trigger | None | No status advance | guard test |
| `recordInstallationEvidenceAction` | Evidence metadata/storage reference | write scope before storage | None | No upload/reference | guard test |
| `authorizeLaunchAction` | Approval and authorized status | write scope + trigger | Customer effect suppressed | No launch transition | guard test |
| `createLaunchHandoffAction` | Handoff and status transition | write scope + trigger | Furnishing intent required for future notification | No handoff | guard test |
| `updateReadinessCheckAction` | Checklist/readiness update | write scope + trigger | None | No readiness change | guard test |
| `assessLaunchReadinessAction` | Readiness assessment | write scope + trigger | None | No assessment/progress change | guard test |
| Scheduling, assignment, reminders, retries, replay, bulk, Admin, RPC | No separate active application call sites found | Same canonical boundary and DB defense | Typed Furnishing notification path | Fail closed | guard/regression tests |
| `getInstallationWorkspace` | Historical reads | Ordinary tenant/role authorization | N/A | Existing records remain readable | FS-007 regressions |

No provider/calendar call, notification enqueue, cache invalidation, or customer
effect can occur after a denied write scope. Non-Furnishing operational workflows
are unchanged; wrong-tenant and anonymous access remains denied by the existing
authorization boundary.
